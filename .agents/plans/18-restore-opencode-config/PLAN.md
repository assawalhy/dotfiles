# Epic 18 — Restore opencode context files and configs on a fresh system

## Goal

A fresh system bootstrapped from this repo plus `setup-os` ends up with the
same opencode context files and configs as this machine. Hybrid, per the user:
**link `AGENTS.md`, jq-seed the JSON configs.**

## Findings (researched, not assumed)

1. **`~/.config/opencode/AGENTS.md` is the file opencode actually reads**, and it
   exists in no repo path. `common/.agents/AGENTS.md` is repo-managed and linked
   to `~/.agents/AGENTS.md` — which opencode does *not* read. So the repo-managed
   global agent instructions are invisible to opencode while a hand-maintained,
   un-restored file is the one in force.

2. **`opencode.json` and `cli.json` are hand-maintained and never created.**
   Nothing in `setup/` writes them. `61-opencode.sh` only installs the binary.

3. **`jq_add_key` returns early when the file is missing** (`agent-tools.sh:55`),
   so it can only ever add to an existing config. On a fresh machine the
   `context7`, `plannotator` and `zvec_grep` MCP entries therefore never land.

4. **`jq` is absent from `setup/packages.list`** (only `jp` is shipped, and
   `jp --indent` is unsupported). Every `agent-tools.sh` jq write no-ops on a
   repo-bootstrapped machine. Also epic 16.

5. **Proved: `jq_add_key` destroys symlinks.** Its `mktemp` → `jq` → `mv "$tmp"
   "$p"` replaces a symlink with a regular file. This is why the JSON configs
   must be jq-seeded rather than linked. The hazard still exists for
   `~/.cursor/mcp.json`.

6. **`--audit` currently reports nothing under opencode** because
   `~/.config/opencode/` is not a linked directory. Linking `AGENTS.md` makes its
   siblings capture candidates for `--refresh` — **including `service.json`,
   which holds a service password.** Ignore entries are required, and the exact
   matching rule for an ignore entry with no repo file is undocumented, so this
   must be verified empirically rather than assumed.

7. **`common/.config/` already commits 9 whole app config dirs** (`lazygit`,
   `nvim`, `ranger`, `wezterm`, `mise`, `mpv`, `delta`, `herdr*`). `opencode` is
   the outlier.

## Approach

```
common/.config/opencode/AGENTS.md   new   linked by link-files
setup/templates/opencode.json      new   seed only
setup/templates/cli.json           new   seed only
setup/steps/68-opencode-config.sh  new   create-if-missing via jq
setup/steps/69-opencode-compaction.sh new epic 16, folded in
setup/packages.list                + jq  (p1)
setup/agent-tools.sh               + create-if-missing in jq_add_key
link-ignore.txt                    + opencode siblings (verified empirically)
```

```
 fresh system                          this machine
 ─────────────                         ────────────
 setup-os                             link-files --fix
   ├ 61-opencode.sh  -> binary          └ common/.config/opencode/AGENTS.md
   ├ 68-opencode-config.sh                  -> ~/.config/opencode/AGENTS.md (symlink)
   │    ├ missing opencode.json?               (the file opencode reads)
   │    │   cp setup/templates/opencode.json
   │    ├ missing cli.json?
   │    │   cp setup/templates/cli.json
   │    └ else: leave existing file untouched
   ├ 69-opencode-compaction.sh
   │    └ jq '.compaction = {...}'  (works on the seeded file)
   └ agent-skills.sh -> ~/.agents/skills/playwright

 never: service.json  (generated by opencode, holds a password)
```

## Decisions

- **Hybrid: link `AGENTS.md`, jq-seed the JSONs** — *(confirmed by user)*. Links
  give real version control and `--audit` drift detection for the one file
  opencode reads; jq seeding avoids the proven `mv`-over-symlink destruction and
  the plugin writers (`zg install`, `jq_add_key`) that share those paths.
- **Templates live in `setup/templates/`** — separately reviewable and
  editor-validated as real `.json`. `setup/` already anticipates non-script
  subdirectories (`setup/skills/`, per the `agent-skills.list` header).
- **Create-if-missing, never overwrite** — an existing file is left alone, so no
  hand edit is ever clobbered.
- **Template drift does not propagate to existing machines** — the accepted cost
  of not linking. `--refresh` handles linked files; these are not linked.
- **`jq_add_key` gains create-if-missing** — one line, removes a whole class of
  silent no-op on fresh machines.
- **No symlink fix in `jq_add_key`** — unnecessary now that opencode's JSONs are
  not linked. Still latent for `~/.cursor/mcp.json`; flagged, not fixed.
- **`service.json` is never committed** — generated by opencode, holds a password.
- **Epic 16 is folded in as step 69** — both write `opencode.json`, so they land
  together and epic 17's steering section targets the now-linked repo file.

## Risks

- **Linking `AGENTS.md` may expose `service.json` to `--refresh`.** It holds a
  service password. Mitigation: run `--audit` immediately after linking, add the
  ignore entries, re-audit, and only then consider any `--refresh`. TODO gates
  this ordering.
- **`zg install --target opencode` writes the ZVEC guidance block into
  `AGENTS.md`** and may replace the symlink with a regular file — unverified.
  Mitigation: content is committed first, so `link-files --fix` restores it
  exactly. Tested explicitly after linking.
- **`cli.json` accumulates machine-specific choices** (keybinds, theme, tabs).
  A template cannot know them, and create-if-missing means the first machine's
  values silently become the template.
- **Epic 17's steering edit must target the repo file**, not the home file, or it
  will be discarded when the symlink is created.
- **Linking `AGENTS.md` is a write to the live machine.** Content is committed
  before `--fix`, and `--diff` shows the change first.

## Verification

- **Fresh-HOME smoke test** — run the steps against a throwaway `HOME` and assert
  `AGENTS.md`, `opencode.json` and `cli.json` all appear, then that re-running is
  a no-op.
- **`bats tests/link-files.bats`** stays at 99 ok — adding a path under
  `common/.config/` must not perturb the link suite.
- **`--audit` shows no `service.json`** after linking and ignoring.
