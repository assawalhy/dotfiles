## 2026-08-15 T4 FIX: neglect semantics were inverted in README (verifier-found, proven)
### The bug
Fixture: context file with ONLY `x11: .Xmodmap`, repo linux/.Xmodmap unlinked.
- WAYLAND (WAYLAND_DISPLAY=wayland-0 DISPLAY=:0): header "audit context: wayland
  (neglecting: x11: .Xmodmap)", .Xmodmap SUPPRESSED (no [missing] line).
- X11 (DISPLAY=:0, no WAYLAND_DISPLAY): header "audit context: x11", .Xmodmap
  REPORTED as `+ .Xmodmap [missing]`.
=> `x11: .Xmodmap` neglects .Xmodmap when the session is NOT x11; reports it when
   the session IS x11 (matches pinned predicate, plan line 136, Metis M7).
My commit ced8606 had TWO inverted spots:
1. --audit subsection said "a line like `x11: .Xmodmap` means --audit neglects
   .Xmodmap when the current session is x11" (contradicting my own next sentence,
   which was correct).
2. "What gets linked" said "paths named there, for the current session context,
   are skipped" (ambiguous/inverted).
### The fix (exact final wording, now in README.md)
Passage 1 (What gets linked):
"`link-context.txt` is the session neglect list for `--audit`: a relpath named
there for a context other than the current session (like `x11: .Xmodmap` under
wayland) is skipped by the link-drift report."
Passage 2 (--audit subsection):
"a line like `x11: .Xmodmap` marks `.Xmodmap` as x11-only, so `--audit` neglects
it on every other session and reports it when the session is x11." (followed by
the kept, already-correct "skipped on a Wayland session and reported on an X11
one").
