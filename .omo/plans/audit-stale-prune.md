# audit-stale-prune - Work Plan

## TL;DR (For humans)

**What you'll get:** `--audit` becomes a smarter health check and a new `--fix` command makes your home exactly match your dotfiles repo: it creates links that are missing, re-points links aimed at the wrong file, backs up and replaces files that collide with the repo, and — the part that used to be impossible — removes leftover links whose repo file was deleted, **including whole folders that vanished from the repo**, plus links that don't belong in your current session (like the X11-only `.Xmodmap` while you're on Wayland). It also understands `link-ignore.txt`: ignore a file that is still linked and the audit shows it as a distinct "ignored" finding that `--fix` un-links; un-ignore a file and the audit shows it as missing again. `--audit` only reports; `--fix` does the work after showing you exactly what it will do.

**Why this approach:** The old code looked for leftover links only inside folders that still exist in the repo — so deleting the last file in a folder made its home links invisible forever. The new approach asks `find` to list every symlink in your home that points into the repo in one fast pass (measured: ~2 seconds on this 60 GB home), then keeps exactly the ones still wanted. A second, new check finds links that are present but neglected for the current session (wayland/x11/headless). Both checks only ever consider symlinks pointing into the repo — everything else in your home is never touched. Because this script deletes and backs up real files, all of it is verified by a committed automated test suite (bats) that runs every edge case against throwaway fake homes — your real home is never modified by testing, only ever inspected read-only.

**What it will NOT do:** It won't change how `--refresh` captures new files, won't let a search pattern override the session-context filter, won't add new session types, won't touch symlinks that don't point into the repo, won't delete your real files without the existing backup safety, and won't change the installer, the picker, or `--diff`. It also won't delete the neglected X11 links automatically — only `--fix` (with its confirmation prompt) does that, and they come back the next time you run the linker on an X11 session.

**Effort:** Medium
**Risk:** Medium - this script deletes/backs up real files under `--force`; every destructive scenario is verified by the bats suite against fixture homes in `$BATS_TEST_TMPDIR`, never the real `$HOME` (only read-only `--audit` and `--fix --dry-run` run against the real machine).

**Decisions to sanity-check:** (1) `--fix` implies `--force` — conflicts get backed up (or deleted with `--no-backup`), so one command completes linking. (2) `--fix` + `--audit` or `--fix` + `--refresh` is an error. (3) The stale scan now finds ANY repo-pointing symlink not in the managed set — including manually-made ones; the safety rule (target must be under `$REPO`) is unchanged. (4) Neglected-but-linked files are reported by `--audit` (`x [neglected]`) and deleted only by `--fix`; dangling neglected links are reported once, as stale. (5) Ignored-but-linked files get their own `i [ignored]` audit category (verified: today they surface as a misleading `stale link`); both ignore directions — entry added → `i`, entry removed → `+ [missing]` — are locked in by tests. (6) Testing is a committed bats suite (`tests/link-files.bats` + `tests/helpers.bash`, plain bash assertions, no bats-assert dependency) that must pass on a clean checkout — so it never asserts the uncommitted `--diff` behavior, and never touches the real `$HOME` (fixture homes only; real machine is only inspected read-only).

- New `--fix` flag: implies `--force`; removes stale + ignored + neglinked; creates missing links; relinks wrong-source links; resolves conflicts (backup unless `--no-backup`); confirmation prompt (`--dry-run` previews, `--yes` skips, `<pattern>` narrows); never opens the picker; errors when combined with `--audit` or `--refresh`.
